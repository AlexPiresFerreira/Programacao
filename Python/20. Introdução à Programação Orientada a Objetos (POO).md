
## Visão geral

A **Programação Orientada a Objetos**, conhecida como **POO**, é um paradigma de programação que organiza o código a partir de **objetos**.

Um objeto combina:

- **Dados**, chamados de atributos;
- **Comportamentos**, representados por métodos.

A POO ajuda a:

- Organizar melhor o código;
- Representar entidades do mundo real;
- Reutilizar código;
- Facilitar a manutenção;
- Criar sistemas mais modulares e extensíveis;
- Esconder detalhes internos de implementação.

> POO não é uma linguagem de programação. É uma forma de pensar e estruturar soluções. Python, Java e C++ são linguagens que oferecem recursos para trabalhar com POO.

# 1. Paradigmas de programação

Um **paradigma de programação** é um estilo ou modelo utilizado para resolver problemas por meio do código.

O paradigma define a forma como o programa é organizado e como as soluções são construídas.

Alguns exemplos de paradigmas são:

- Programação imperativa ou procedural;
- Programação funcional;
- Programação orientada a eventos;
- Programação orientada a objetos.

## Exemplo

Problema: **beber água**

Possíveis soluções:

- Usar um copo;
- Usar uma garrafa;
- Usar uma caneca.

O problema é o mesmo, mas a forma de solucioná-lo pode variar. Cada paradigma oferece uma maneira diferente de organizar a solução.

# 2. Classes e objetos

## O que é uma classe?

Uma **classe** é um modelo ou estrutura que define as características e os comportamentos de um tipo de objeto.

Ela funciona como uma espécie de molde.

Uma classe pode definir:

- Atributos;
- Métodos;
- Regras de funcionamento;
- Estado inicial dos objetos.

## O que é um objeto?

Um **objeto** é uma instância de uma classe.

A classe define como o objeto deve ser, enquanto o objeto é a entidade concreta que pode ser utilizada no programa.

### Exemplo conceitual

- Classe: `Cachorro`;
- Objetos: `cao_1` e `cao_2`;
- Atributos: nome, cor e estado;
- Métodos: latir e dormir.

---

## Criando uma classe

```python
class Cachorro:
    def __init__(self, nome, cor, acordado=True):
        self.nome = nome
        self.cor = cor
        self.acordado = acordado

    def latir(self):
        print("Au au!")

    def dormir(self):
        self.acordado = False
        print("Zzzzz...")
```

## Criando objetos

```python
cao_1 = Cachorro("Chappie", "amarelo", False)
cao_2 = Cachorro("Aladim", "branco e preto")
```

Cada objeto possui seus próprios valores:

```python
print(cao_1.nome)
# Chappie

print(cao_2.nome)
# Aladim

print(cao_2.acordado)
# True
```

Também podemos chamar os métodos:

```python
cao_1.latir()
# Au au!

cao_2.dormir()
# Zzzzz...

print(cao_2.acordado)
# False
```

# 3. Atributos e métodos

## Atributos

Atributos representam os dados ou características de um objeto.

No exemplo do cachorro:

```python
self.nome
self.cor
self.acordado
```

Esses atributos armazenam informações específicas de cada objeto.

## Métodos

Métodos são funções definidas dentro de uma classe. Eles representam os comportamentos do objeto.

```python
def latir(self):
    print("Au au!")
```

```python
def dormir(self):
    self.acordado = False
    print("Zzzzz...")
```

## O parâmetro `self`

O parâmetro `self` representa a própria instância que está executando o método.

Ele é utilizado para acessar:

- Atributos do objeto;
- Outros métodos do objeto.

```python
class Cachorro:
    def __init__(self, nome):
        self.nome = nome

    def apresentar(self):
        print(f"Meu nome é {self.nome}.")
```

Quando chamamos:

```python
cao = Cachorro("Aladim")
cao.apresentar()
```

O Python passa o objeto `cao` automaticamente como argumento para `self`.

> `self` é uma convenção obrigatória para métodos de instância. Ele não é uma palavra reservada, mas deve ser utilizado com esse nome por convenção da comunidade Python.

# 4. Primeiro exemplo de POO

Uma bicicletaria precisa registrar bicicletas vendidas. Cada bicicleta possui:

- Cor;
- Modelo;
- Ano;
- Valor.

Ela também pode:

- Buzinar;
- Parar;
- Correr.

```python
class Bicicleta:
    def __init__(self, cor, modelo, ano, valor):
        self.cor = cor
        self.modelo = modelo
        self.ano = ano
        self.valor = valor

    def buzinar(self):
        print("Plim plim!")

    def parar(self):
        print("A bicicleta parou.")

    def correr(self):
        print("A bicicleta está correndo.")
```

Criando e utilizando um objeto:

```python
bicicleta = Bicicleta(
    cor="vermelha",
    modelo="Caloi",
    ano=2024,
    valor=1500
)

print(bicicleta.cor)
print(bicicleta.modelo)
print(bicicleta.ano)
print(bicicleta.valor)

bicicleta.buzinar()
bicicleta.correr()
bicicleta.parar()
```

# 5. Método construtor `__init__`

O método `__init__` é executado automaticamente quando uma nova instância da classe é criada.

Ele é utilizado para inicializar o estado do objeto.

```python
class Pessoa:
    def __init__(self, nome, idade):
        self.nome = nome
        self.idade = idade
```

Ao criar um objeto:

```python
pessoa = Pessoa("Alex", 25)
```

O método `__init__` é chamado automaticamente com os valores informados.

## Parâmetros padrão no construtor

```python
class Conta:
    def __init__(self, saldo=0):
        self.saldo = saldo
```

Agora podemos criar uma conta sem informar o saldo:

```python
conta_1 = Conta()
conta_2 = Conta(1000)

print(conta_1.saldo)
# 0

print(conta_2.saldo)
# 1000
```

> Tecnicamente, `__init__` inicializa o objeto. A criação da instância está relacionada ao método especial `__new__`, que normalmente não precisa ser sobrescrito em situações comuns.

# 6. Método destrutor `__del__`

O método `__del__` pode ser executado quando um objeto está sendo destruído.

```python
class Exemplo:
    def __del__(self):
        print("Objeto destruído.")
```

```python
objeto = Exemplo()

del objeto
```

## Atenção ao uso de `__del__`

O `__del__` não deve ser utilizado como mecanismo principal para liberar recursos importantes, como:

- Arquivos;
- Conexões com banco de dados;
- Conexões de rede;
- Recursos externos.

O momento exato da execução de `__del__` pode variar, pois depende do gerenciamento de memória e do coletor de lixo.

Para liberar recursos de forma confiável, prefira:

- `with`;
- Métodos explícitos de encerramento;
- Gerenciadores de contexto.

```python
with open("arquivo.txt", "w") as arquivo:
    arquivo.write(" conteúdo")
```

# 7. Herança

**Herança** é o mecanismo que permite que uma classe filha reutilize atributos e métodos de uma classe pai.

- A classe pai também pode ser chamada de classe base ou superclasse;
- A classe filha também pode ser chamada de subclasse.

## Sintaxe

```python
class ClassePai:
    pass


class ClasseFilha(ClassePai):
    pass
```

## Exemplo

```python
class Animal:
    def comer(self):
        print("O animal está comendo.")


class Cachorro(Animal):
    def latir(self):
        print("Au au!")
```

O objeto `Cachorro` possui o método definido na própria classe e também o método herdado de `Animal`:

```python
cachorro = Cachorro()

cachorro.comer()
# O animal está comendo.

cachorro.latir()
# Au au!
```

---

## Benefícios da herança

A herança pode:

- Reutilizar código;
- Evitar duplicação;
- Representar relações entre classes;
- Permitir especializações;
- Facilitar a extensão de funcionalidades.

A herança também é transitiva:

```text
Classe C herda de B
Classe B herda de A

C também recebe características herdadas de A
```

---

## Herança simples

A herança simples ocorre quando uma classe filha herda de apenas uma classe pai.

```python
class Pessoa:
    pass


class Estudante(Pessoa):
    pass
```

---

## Herança múltipla

A herança múltipla ocorre quando uma classe herda de mais de uma classe pai.

```python
class Nadador:
    def nadar(self):
        print("Nadando...")


class Corredor:
    def correr(self):
        print("Correndo...")


class Triatleta(Nadador, Corredor):
    pass
```

Uso:

```python
atleta = Triatleta()

atleta.nadar()
atleta.correr()
```

> A herança múltipla deve ser utilizada com cuidado, pois pode tornar a estrutura do programa mais complexa.

# 8. Encapsulamento

**Encapsulamento** é o conceito de agrupar:

- Dados;
- Métodos que manipulam esses dados.

Ele ajuda a controlar o acesso ao estado interno do objeto e reduz alterações acidentais.

## Exemplo conceitual

Uma classe `Conta` pode possuir:

- Um saldo;
- Um método para depositar;
- Um método para sacar.

O saldo não deveria ser alterado livremente sem regras.

```python
class Conta:
    def __init__(self, saldo=0):
        self._saldo = saldo

    def depositar(self, valor):
        if valor > 0:
            self._saldo += valor

    def sacar(self, valor):
        if 0 < valor <= self._saldo:
            self._saldo -= valor
            return True

        return False

    def consultar_saldo(self):
        return self._saldo
```

Uso:

```python
conta = Conta(1000)

conta.depositar(500)
conta.sacar(200)

print(conta.consultar_saldo())
# 1300
```

# 9. Recursos públicos e privados

Python não possui modificadores de acesso tradicionais como `public`, `private` e `protected` de algumas outras linguagens.

Em Python, são utilizadas convenções de nomenclatura.

## Atributo público

Um recurso sem sublinhado inicial é considerado público.

```python
class Pessoa:
    def __init__(self, nome):
        self.nome = nome
```

Pode ser acessado diretamente:

```python
pessoa = Pessoa("Alex")

print(pessoa.nome)
```

## Atributo protegido por convenção

Um único sublinhado indica que o recurso é interno ou protegido por convenção.

```python
class Conta:
    def __init__(self, saldo):
        self._saldo = saldo
```

O atributo ainda pode ser acessado:

```python
conta = Conta(1000)

print(conta._saldo)
```

Porém, o sublinhado indica que ele não deveria ser manipulado diretamente fora da classe.

## Atributo com nome modificado

Dois sublinhados no início ativam o mecanismo de _name mangling_.

```python
class Conta:
    def __init__(self, saldo):
        self.__saldo = saldo
```

O acesso direto deixa de funcionar da forma esperada:

```python
conta = Conta(1000)

# print(conta.__saldo)  # AttributeError
```

Internamente, o nome é alterado para algo semelhante a:

```python
_conta__saldo
```

Ainda assim, isso não representa uma proteção absoluta. O objetivo principal é evitar conflitos acidentais de nomes, especialmente em herança.

# 10. Properties

A função `property()` e o decorador `@property` permitem criar atributos gerenciados.

Uma propriedade permite:

- Controlar a leitura de um atributo;
- Validar valores antes de armazená-los;
- Controlar alterações;
- Manter uma API pública estável mesmo que a implementação interna mude.

## Exemplo com `@property`

```python
class Conta:
    def __init__(self, saldo=0):
        self._saldo = saldo

    @property
    def saldo(self):
        return self._saldo

    @saldo.setter
    def saldo(self, valor):
        if valor < 0:
            raise ValueError("O saldo não pode ser negativo.")

        self._saldo = valor
```

Uso:

```python
conta = Conta(1000)

print(conta.saldo)
# 1000

conta.saldo = 1500

print(conta.saldo)
# 1500
```

Tentativa inválida:

```python
conta.saldo = -100
# ValueError: O saldo não pode ser negativo.
```

## Property somente leitura

Se definirmos apenas o getter, a propriedade poderá ser lida, mas não alterada diretamente.

```python
class Pessoa:
    def __init__(self, nome, sobrenome):
        self._nome = nome
        self._sobrenome = sobrenome

    @property
    def nome_completo(self):
        return f"{self._nome} {self._sobrenome}"
```

```python
pessoa = Pessoa("Alex", "Silva")

print(pessoa.nome_completo)
# Alex Silva
```

## Property com deleter

Também é possível definir o comportamento de `del`.

```python
class Exemplo:
    def __init__(self, valor):
        self._valor = valor

    @property
    def valor(self):
        return self._valor

    @valor.deleter
    def valor(self):
        self._valor = None
```

```python
objeto = Exemplo(10)

print(objeto.valor)
# 10

del objeto.valor

print(objeto.valor)
# None
```

# 11. Polimorfismo

A palavra **polimorfismo** significa “muitas formas”.

Em POO, polimorfismo ocorre quando diferentes objetos respondem ao mesmo método de maneiras diferentes.

## Polimorfismo em funções built-in

A função `len()` trabalha com diferentes tipos de objetos:

```python
print(len("Python"))
# 6

print(len([10, 20, 30]))
# 3
```

A função é a mesma, mas o comportamento depende do objeto recebido.

---

## Polimorfismo com herança

Uma classe filha pode sobrescrever um método herdado da classe pai.

```python
class Passaro:
    def voar(self):
        print("O pássaro está voando.")


class Pardal(Passaro):
    def voar(self):
        print("O pardal está voando.")


class Avestruz(Passaro):
    def voar(self):
        print("A avestruz não pode voar.")
```

Podemos criar uma função que trabalha com qualquer objeto que possua o método `voar()`:

```python
def plano_de_voo(passaro):
    passaro.voar()
```

Uso:

```python
plano_de_voo(Pardal())
# O pardal está voando.

plano_de_voo(Avestruz())
# A avestruz não pode voar.
```

A função `plano_de_voo()` não precisa saber exatamente qual é o tipo do objeto. Ela apenas precisa que o objeto forneça o comportamento esperado.

> Esse estilo é conhecido como **duck typing**: se um objeto se comporta como um determinado tipo, ele pode ser utilizado daquela forma.

# 12. Variáveis de instância

Variáveis de instância pertencem a um objeto específico.

Cada instância possui seus próprios valores.

```python
class Estudante:
    def __init__(self, nome, numero):
        self.nome = nome
        self.numero = numero
```

```python
aluno_1 = Estudante("Guilherme", 56451)
aluno_2 = Estudante("Giovanna", 17323)

print(aluno_1.nome)
# Guilherme

print(aluno_2.nome)
# Giovanna
```

Alterar um objeto não altera automaticamente o outro:

```python
aluno_1.nome = "Alex"

print(aluno_1.nome)
# Alex

print(aluno_2.nome)
# Giovanna
```

# 13. Variáveis de classe

Variáveis de classe pertencem à classe e são compartilhadas pelas instâncias.

```python
class Estudante:
    escola = "DIO"

    def __init__(self, nome, numero):
        self.nome = nome
        self.numero = numero
```

Os objetos conseguem acessar o atributo da classe:

```python
aluno_1 = Estudante("Guilherme", 56451)
aluno_2 = Estudante("Giovanna", 17323)

print(aluno_1.escola)
# DIO

print(aluno_2.escola)
# DIO
```

A variável de classe também pode ser acessada diretamente pela classe:

```python
print(Estudante.escola)
# DIO
```

## Alterando a variável de classe

```python
Estudante.escola = "Nova Escola"

print(aluno_1.escola)
# Nova Escola

print(aluno_2.escola)
# Nova Escola
```

## Cuidado com atribuição pela instância

```python
aluno_1.escola = "Escola Particular"
```

Nesse caso, é criada uma variável de instância chamada `escola` apenas para `aluno_1`. A variável de classe não é alterada.

```python
print(aluno_1.escola)
# Escola Particular

print(aluno_2.escola)
# Nova Escola
```

---

## Exemplo com `__str__`

O método especial `__str__` define uma representação textual amigável do objeto.

```python
class Estudante:
    escola = "DIO"

    def __init__(self, nome, numero):
        self.nome = nome
        self.numero = numero

    def __str__(self):
        return f"{self.nome} ({self.numero}) - {self.escola}"
```

```python
aluno = Estudante("Guilherme", 56451)

print(aluno)
# Guilherme (56451) - DIO
```

Eles recebem `self` como primeiro parâmetro e podem acessar:

- Atributos da classe;
- Outros métodos.

```python
class Pessoa:
    def __init__(self, nome):

```

```python
pessoa = Pessoa("Alex")

print(pessoa.apresentar())
```

# 15. Métodos de classe

Métodos de classe estão ligados à classe, e não a uma instância específica.

São definidos com o decorador `@classmethod` e recebem `cls` como primeiro parâmetro.

```python
class Pessoa:
    especie = "Humano"

    @classmethod
    def exibir_especie(cls):
        return cls.especie
```

Uso:

```python
print(Pessoa.exibir_especie())
# Humano
```

Também podem ser chamados por uma instância:

```python
pessoa = Pessoa()

print(pessoa.exibir_especie())
# Humano
```

Porém, o uso mais comum é chamá-los pela própria classe.

## Método de classe como fábrica

Métodos de classe são frequentemente utilizados como **métodos de fábrica**, criando objetos de maneiras alternativas.

```python
class Pessoa:
    def __init__(self, nome, idade):
        self.nome = nome
        self.idade = idade

    @classmethod
    def de_string(cls, texto):
        nome, idade = texto.split(",")
        return cls(nome, int(idade))
```

```python
pessoa = Pessoa.de_string("Alex,25")

print(pessoa.nome)
# Alex

print(pessoa.idade)
# 25
```

# 16. Métodos estáticos

Métodos estáticos são definidos com `@staticmethod`.

Eles:

- Não recebem `self`;
- Não recebem `cls`;
- Não acessam automaticamente o estado da instância;
- Não acessam automaticamente o estado da classe;
- Geralmente representam funções utilitárias relacionadas à classe.

```python
class Matematica:
    @staticmethod
    def somar(a, b):
        return a + b
```

Uso:

```python
print(Matematica.somar(2, 3))
# 5
```

## Outro exemplo

```python
class Validador:
    @staticmethod
    def cpf_valido(cpf):
        cpf = cpf.replace(".", "").replace("-", "")
        return len(cpf) == 11
```

```python
print(Validador.cpf_valido("123.456.789-00"))
# True
```

---

## Diferença entre métodos

|Tipo de método|Primeiro parâmetro|Acesso principal|Uso comum|
|---|---|---|---|
|Instância|`self`|Estado do objeto|Operações específicas de um objeto|
|Classe|`cls`|Estado da classe|Métodos de fábrica e operações da classe|
|Estático|Nenhum obrigatório|Não recebe estado automaticamente|Funções utilitárias relacionadas à classe|

# 17. Classes abstratas

Uma classe abstrata define um **contrato** que deve ser seguido pelas classes filhas.

Uma interface define principalmente:

- O que uma classe deve fazer;
- Quais métodos ela precisa implementar.

Ela não define necessariamente como o comportamento será implementado.

## Classes abstratas em Python

Python fornece o módulo `abc`, que significa **Abstract Base Classes**.

Os principais recursos são:

- `ABC`: classe base para classes abstratas;
- `abstractmethod`: decorador para métodos abstratos.

```python
from abc import ABC, abstractmethod
```

## Criando uma classe abstrata

```python
from abc import ABC, abstractmethod


class Forma(ABC):
    @abstractmethod
    def calcular_area(self):
        pass
```

A classe `Forma` define que toda classe concreta deverá implementar `calcular_area()`.

## Implementando a classe abstrata

```python
class Retangulo(Forma):
    def __init__(self, largura, altura):
        self.largura = largura
        self.altura = altura

    def calcular_area(self):
        return self.largura * self.altura
```

Uso:

```python
retangulo = Retangulo(10, 5)

print(retangulo.calcular_area())
# 50
```

## Classes abstratas não podem ser instanciadas

```python
# forma = Forma()
```

Esse código gera um erro porque `Forma` possui um método abstrato que não foi implementado.

A classe filha precisa implementar todos os métodos abstratos para poder ser instanciada.

# 18. Exemplo completo com POO

O exemplo abaixo combina:

- Classe;
- Atributos;
- Métodos;
- Encapsulamento;
- Property;
- Classe filha;
- Polimorfismo.

```python
from abc import ABC, abstractmethod


class Conta(ABC):
    def __init__(self, titular, saldo=0):
        self.titular = titular
        self._saldo = saldo

    @property
    def saldo(self):
        return self._saldo

    def depositar(self, valor):
        if valor <= 0:
            raise ValueError("O valor do depósito deve ser positivo.")

        self._saldo += valor

    def sacar(self, valor):
        if valor <= 0:
            raise ValueError("O valor do saque deve ser positivo.")

        if valor > self._saldo:
            return False

        self._saldo -= valor
        return True

    @abstractmethod
    def tipo_conta(self):
        pass

    def __str__(self):
        return (
            f"Titular: {self.titular} | "
            f"Saldo: R$ {self.saldo:.2f} | "
            f"Tipo: {self.tipo_conta()}"
        )


class ContaCorrente(Conta):
    def tipo_conta(self):
        return "Conta corrente"


class ContaPoupanca(Conta):
    def tipo_conta(self):
        return "Conta poupança"
```

Uso:

```python
conta_1 = ContaCorrente("Alex", 1000)
conta_2 = ContaPoupanca("Maria", 500)

conta_1.depositar(250)
conta_2.sacar(100)

print(conta_1)
print(conta_2)
```

O método `tipo_conta()` possui comportamentos diferentes nas classes filhas. Isso representa polimorfismo.

# 19. Os principais conceitos da POO

Os quatro conceitos mais conhecidos da programação orientada a objetos são:

## Abstração

Representar apenas os detalhes importantes de uma entidade, escondendo complexidades desnecessárias.

Exemplo:

```python
carro.ligar()
```

O usuário não precisa conhecer todos os detalhes internos para utilizar o método.

## Encapsulamento

Agrupar dados e comportamentos, controlando o acesso ao estado interno do objeto.

Exemplo:

```python
conta.depositar(100)
```

Em vez de alterar o saldo diretamente, utilizamos um método que pode validar a operação.

## Herança

Permitir que uma classe reutilize características e comportamentos de outra.

```python
class Cachorro(Animal):
    pass
```

## Polimorfismo

Permitir que objetos diferentes respondam ao mesmo método de maneiras diferentes.

```python
animal.emitir_som()
```

Cada classe filha pode implementar seu próprio comportamento.

# 20. Erros e cuidados comuns

## Confundir classe e objeto

```python
class Pessoa:
    pass

pessoa = Pessoa()
```

- `Pessoa` é a classe;
- `pessoa` é o objeto ou instância.

---

## Esquecer o `self`

Incorreto:

```python
class Pessoa:
    def __init__(nome):
        self.nome = nome
```

Correto:

```python
class Pessoa:
    def __init__(self, nome):
        self.nome = nome
```

---

## Esquecer de usar `self` no atributo

Incorreto:

```python
class Pessoa:
    def __init__(self, nome):
        nome = nome
```

Nesse caso, apenas a variável local é atribuída.

Correto:

```python
class Pessoa:
    def __init__(self, nome):
        self.nome = nome
```

---

## Alterar atributos internos diretamente

Evite:

```python
conta._saldo = -1000
```

Prefira métodos ou propriedades que validem os dados:

```python
conta.depositar(100)
conta.sacar(50)
```

---

## Instanciar uma classe abstrata

```python
from abc import ABC, abstractmethod


class Animal(ABC):
    @abstractmethod
    def emitir_som(self):
        pass
```

```python
# animal = Animal()
```

A classe não pode ser instanciada enquanto possuir métodos abstratos não implementados.

---

## Utilizar herança sem necessidade

Nem todo relacionamento entre classes deve ser resolvido com herança.

Use herança quando existir uma relação clara de:

```text
é um
```

Exemplos:

- Cachorro é um animal;
- Gerente é um funcionário;
- Retângulo é uma forma geométrica.

Quando a relação for:

```text
tem um
```

pode ser mais apropriado utilizar composição.

Exemplo:

- Carro tem um motor;
- Computador tem uma placa-mãe;
- Pedido tem itens.

---

# 21. Herança versus composição

## Herança

Representa uma relação de especialização:

```python
class Animal:
    pass


class Cachorro(Animal):
    pass
```

Um cachorro **é um** animal.

## Composição

Representa uma relação em que um objeto possui outro objeto.

```python
class Motor:
    def ligar(self):
        print("Motor ligado.")


class Carro:
    def __init__(self):
        self.motor = Motor()

    def ligar(self):
        self.motor.ligar()
```

Um carro **tem um** motor.

> Em muitos casos, composição torna o código mais flexível do que uma hierarquia profunda de herança.

# 22. Boas práticas em POO

- Use nomes de classes em `PascalCase`;
- Use nomes de métodos e atributos em `snake_case`;
- Defina classes com responsabilidades claras;
- Evite classes muito grandes;
- Use métodos pequenos e objetivos;
- Utilize `__init__` para inicializar o estado do objeto;
- Prefira métodos e propriedades para controlar alterações importantes;
- Evite modificar atributos internos diretamente;
- Use `@property` para validações e atributos gerenciados;
- Utilize herança apenas quando houver uma relação clara;
- Prefira composição quando ela representar melhor o problema;
- Use classes abstratas para definir contratos;
- Evite utilizar `__del__` para liberar recursos críticos;
- Documente classes e métodos importantes;
- Utilize polimorfismo para reduzir condicionais baseadas em tipos;
- Evite heranças muito profundas e complexas.
